## Findings (checked before filing, now in #57's Problem section)
- **Logs double-count:** 1,061 usage lines covered only 521 API calls. The docs say to deduplicate by message ID.
- **The `cost-state` total covers less than the log:** 12.7M cache reads against ~287M in the file. It appears to reset on resume.
- **Some calls never reach the log:** `cost-state` includes Haiku calls the conversation log never shows (background helpers).
- **Output counts are contested:** the docs say per-step `output_tokens` is a placeholder, but this log's values look real (median 745). Left open, and #58 settles it by probe.
- **All USD figures are client-side estimates** (docs). Authoritative billing is the Usage and Cost API.
- **Hooks:** `SubagentStop` gets `agent_transcript_path`, and `SessionEnd` has a `reason`.
- **OpenTelemetry:** cost and token metrics carry `agent.name` and `skill.name`.
- **Headless runs:** `claude -p` JSON includes `total_cost_usd`. `--bare` skips project assets, so it's useless for asset-level levers.

## Gotchas & dead ends (the live /epic run)
- **This personal-account repo has issue types** (Task, Bug, Feature), which vindicates not
  claiming "personal repos have none". There's no Epic type and no `epic` label: epics used the
  `Epic: ` title prefix, and **no label was created**, which is left for the user to decide.
- **Filing 13 issues took about 30 MCP calls**: create, `fill-self`, update, per child. Every child
  had to be re-rendered once its sibling numbers existed. A throwaway helper (`gen.py`: values
  with `@KEY` references to earlier issues, `render`/`fill`) made it workable. **A batch mode for
  `issue_body.py`** (manifest in, ordered filing plan out) is the obvious follow-up if `/epic` gets
  used often. File it then, not now.
- Two content slips were caught before filing (an agent that "applies" the catalog, and a scope
  that contradicted its acceptance). Rendering through the check didn't catch them. Reading did.
